# Security Policy

## Supported version

Security fixes are applied to the latest revision of the default branch. This project is pre-release and does not maintain older supported release lines.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion, or pull request.

Once the repository is hosted on GitHub, use its private **Report a vulnerability** form under the Security tab. Include:

- the affected file, route, or dependency;
- steps to reproduce;
- expected impact;
- any suggested mitigation; and
- whether the report may involve personal or security-sensitive building information.

If private vulnerability reporting is not available, contact the repository owner through a private channel and ask for a secure reporting path without including exploit details in the first message.

The maintainer will acknowledge a complete report as soon as practical, validate it, and coordinate a fix and disclosure timeline. Please avoid accessing data that is not yours and stop testing once impact is demonstrated.

## Scope

The app is a static room viewer with no accounts, uploads, application API, or analytics. Reports about source provenance, privacy, unsafe external links, dependency integrity, generated assets, and deployment headers are still in scope.
